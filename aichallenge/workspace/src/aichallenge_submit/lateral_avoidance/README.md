# lateral_avoidance

前方のカートの後ろに並ぶのではなく、**横に避けて走り続ける**ためのノード。

**既定は OFF (`use_lateral_avoidance:=true` で有効化)。** 実装・配線・テストは揃っていて
guard の介入を測定可能なだけ減らすが、**ラップタイムは改善しない**。理由は下の実測にある。

## 位置づけ

```
MPC --/control/command/control_cmd_mpc--> lateral_avoidance --/control/command/control_cmd_avoided-->
     collision_guard --/control/command/control_cmd_guarded--> stuck_recovery --> vehicle
```

**guard より前**に置くのが設計の肝。guard は障害物を「自車が実際に乗っている円弧」に
対して判定するので、こちらが舵を切った時点でカートが guard のコリドーから外れ、
速度制限が**自動的に解放される**。ノード間で協調する必要はなく、幾何がそうしてくれる。
guard は縦方向のみ、このノードは横方向のみを担当し、互いに打ち消し合わない。

## 判断

| 項目 | 既定値 | 理由 |
|---|---|---|
| `pass_clearance` | 1.6 m | 1.45 m のカート2台が並ぶには中心間 1.5 m 必要。測位誤差の余裕込み |
| `max_offset` | 1.6 m | **走行面を出ないための歯止め**。MPC 内蔵の回避はこれが無く、2.0〜2.3 m 外まで振って車体を路肩に座礁させた |
| `preview_distance` | 12.0 m | |
| `min_preview_distance` | 0.5 m | 3.0 m だと**一番必要な至近距離で盲目になる**（下記） |
| `max_curvature_bias` | 0.25 1/m | フルロック 0.58 に対して十分内側 |

**どちらにも余地が無ければ回避しない。** `max_offset` に収まる側が無いときはバイアスを
一切出さず、guard に減速させる。カートの後ろにつくのは秒の損失だが、走行面を出るのは
セッションの損失（実測 0 周）。

`steering_tire_angle` は**角度ではなく曲率 × ゲイン**を運ぶ。`tan()/wheel_base` を掛けるのは
誤り。詳細は `avoidance.py` の docstring。

## 実測 1: 至近距離で盲目になっていた (2026-08-16)

`min_preview_distance` の初期値 3.0 m は、**guard が静止カートの 0.73 m 手前で車を止める**
という事実と噛み合っていなかった。回避は 4.5 m で一度発火したきり残り 600 秒沈黙し、
guard の速度制限 603 回で **0 周**。0.5 m に下げると制限は 12 回に激減し、車は
0.73 m → 0.39 m まで詰めた。

ただし**そこで再び停止した**。横に動くには前進が必要で、前進は guard が止める。
**グリッド上で真正面の静止カートに鼻を突き合わせた状態は、このノードでは解けない**
（後退が要る＝`stuck_recovery` の領分だが、あちらは 2 m/s に達するまで武装しないので
発進前は動かない）。

## 実測 2: 走行中の低速カート — 対照実験あり (2026-08-16)

`dev.sh` + `fake_v2x_publisher` の 20 km/h カート、guard は両方 ON。

| | 回避 ON | 回避 OFF |
|---|---|---|
| guard の速度制限 | **34.0 回/周** | 58.0 回/周 |
| ラップ中央値 | 62.7 s | **62.7 s** |
| ラップの幅 | 54.1〜71.2 s | 58.6〜66.8 s |
| 緊急停止 / 復帰 | 5 / 8 | 2 / 3 |

**guard の介入は 41% 減った。しかしペースは一切変わっていない。** 対照側は 40 周連続で
62.6〜62.7 秒に貼り付いており、これは 20 km/h の NPC にロックされた状態そのもの。
回避 ON でも中央値は同じで、緊急停止と復帰はむしろ増えている。

## なぜ抜けないのか（次の一手）

**指令にバイアスを足す方式の構造的な限界。** MPC はレースラインを追従するフィードバック
制御なので、こちらが足した横方向のバイアスを MPC 自身が打ち消しにくる。オフセットを
保持するには**指令ではなく参照（目標 `e_y`）を動かす**必要がある。

つまり次は「MPC の参照ラインを横にずらす」実装であって、このノードの調整ではない。
なお MPC 内蔵の `use_obstacle_avoidance` はコリドー方式で、こちらは別の理由
（到達可能性）で詰んでいる — `multi_purpose_mpc_ros` 側の記録を参照。
